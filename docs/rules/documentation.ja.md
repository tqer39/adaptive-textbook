# ドキュメントのルール

[English](documentation.md) | [日本語](documentation.ja.md)

## 言語とファイル名

公開ドキュメントの標準言語は英語です。英語は`README.md`や`docs/topic.md`、
日本語は隣接する`README.ja.md`や`docs/topic.ja.md`に記載します。
ルート・Apple・ハーネスのREADMEと、`docs/`以下のすべてのMarkdown文書が対象です。
この規約は、アプリUIや教材本文の英語対応を意味しません。

各ページのH1直下に、相対ファイル名を使った言語切替を置きます。

```markdown
[English](topic.md) | [日本語](topic.ja.md)
```

通常の文書リンクは同じ言語へ向けます。日本語版からは`topic.ja.md`、
英語版からは`topic.md`へリンクします。外部URL、ソースのパス、API識別子は維持します。

`AGENTS.md`はツールが自動検出するファイル名のため、その名前のまま、短い英語版を1つだけ置きます。
`AGENTS.ja.md`を作成せず、`CLAUDE.md`への規約の重複や、
全ドキュメントの翻訳をエージェントの起動コンテキストへ読み込むことも避けます。
同様に、`.agents/skills/*/SKILL.md`はツールが自動検出する英語の入口とし、`SKILL.ja.md`は作成しません。
人間向けのスキル利用案内は、英日対の[ネイティブ開発ガイド](../native-harness.ja.md)に記載します。
機械可読な検証証拠やローカル生成物には翻訳版を作る必要はありません。

## 作業の影響範囲だけを更新する

1. 実際の動作や契約の変更から、影響する文書を特定します。
   ファイルを開く前に、ファイル名・差分・対象を絞った`rg`検索を使います。
2. 関連する英語の節を読みます。日本語版は、対応する節の更新や用語の維持に必要な部分だけ読みます。
3. その英語の節を編集し、同じ変更内で日本語の対応する節にも同等の変更を反映します。
   日本語で依頼された場合も、英語版を更新します。
4. 無関係な段落・書式・過去の記録には触れません。小さなコード変更のたびに、
   ページ全体の再翻訳、全ドキュメントの巡回、文書ツリー全体の再生成は行いません。
5. 文書化された動作・設定手順・契約に変更がなければ、ドキュメントは変更しません。

翻訳のずれを解消する際の基準は英語版ですが、技術的な事実の根拠はコードと検証済みの証拠です。
英語で書かれているという理由だけで、主張を維持しないでください。
矛盾は実装に照らして解消するか、不確実な点として報告します。
公開ページを新設する場合は両言語版を追加します。全体の言語移行は独立した作業として扱い、
通常の実装作業のたびに繰り返しません。

## 内容と証拠

- 両言語版で、範囲・前提条件・動作・制約・安全上の境界を揃えます。
  一方を要約版に置き換えたり、新しい手順を未翻訳のまま放置したりしません。
- 実行例、フラグ、環境変数、JSONキー、パス、URL、モデルID、版、日付、費用、測定値を維持します。
  検証データや実際のUIラベルは例の中で日本語のままでも構いません。周囲の英語本文で説明します。
- 詳細な説明はトピックごとに1か所へ置き、リンクで参照します。
  大きな例や詳細ルールをREADME・`AGENTS.md`・複数の解説ページへ複製しません。
- 改行は文や段落の境界に置きます。桁数に合わせるために無関係な本文を折り返し直しません。
  リンク・表・両言語の構造を維持できるよう、`MD013`は無効にします。
- 実装済みの動作、完了した検証、提案を区別します。性能や実モデル検証には日付と条件を記載します。
  ビルド成功を、画面操作の実行確認として扱いません。
- 過去の調査・開発記録は、記録時点の状況を示します。
  過去の価格・版・監査結果を新しい調査結果として扱いません。
  版に依存する主張を変更する作業では、現在の一次情報を確認します。
- 秘密情報、実APIキー、個人のパス、生の認証情報は公開ドキュメントへ記載しません。

## 検証

`npm run docs:check`で、言語ペア・言語切替・ローカルのMarkdownリンクを簡易検査します。
モデル呼出しやネットワーク接続を使わず、文書の構造を確認します。
Markdownを編集したら、上記の検査とMarkdown lintを含む`mise run lint`を実行します。
両言語版と、下位ディレクトリの規約ページもlintの対象にします。
スキルの入口もlint対象にし、`docs:check`で正本のルール・ガイド・ソース・スクリプトへのリンクを検証します。

変更した節の意味とコマンドの維持をレビューします。自動検査だけでは翻訳の正確さを証明できません。
文書だけの変更では、変更した実行例の確認が必要な場合を除き、アプリのビルド・
実エージェントのループ・10万記事ベンチマークを再実行しません。
